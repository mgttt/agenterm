# 超控智能体 v7 — 规则引擎自驱 + LLM 节制调用

> v7（2026-08-09）。回应两个核心约束：**自驱**（不能只等命令）和**省 token**（不能每步都调 LLM）。
> 解法：规则引擎负责 90% 的日常自驱行为（不费 token），LLM 只在高价值节点介入。

---

## 0. Token 消耗分析

v6 的隐藏问题：如果每步都走 LLM——

```
创建 Task        → LLM 理解意图         ~500 tokens
每步推进提示      → LLM 生成回复         ~200 tokens × 4 步 = ~800
切回恢复上下文    → LLM 总结上下文        ~300 tokens
每天结束报告      → LLM 生成日报          ~800 tokens
─────────────────────────────────────────────────
一个 4 步 Task  ≈ 2,400 tokens
一天 5 个 Task   ≈ 12,000 tokens（仅超控智能体，不含实际工作）
```

实际上 80% 的交互不需要 LLM。规则引擎就够了。

## 1. 四层架构

```
┌─ UI 层 ───────────────────────────────────────────────┐
│ Task 看板 · 步骤条 · 通知 · 卡片                         │
│ 纯渲染。零 token 消耗。                                   │
└──────────────────────┬───────────────────────────────┘
                       │ 结构化状态
┌─ 规则引擎 ────────────────────────────────────────────┐
│ 事件 → 规则匹配 → 动作                                   │
│ "tab @2 输出 '3 passed, 1 failed'"                    │
│   → 匹配规则: exit_code != 0                          │
│   → 動作: 步骤标记失败 + 通知 + [重新跑] 按钮            │
│                                                       │
│ 零 token 消耗。确定性。                                  │
└──────────────────────┬───────────────────────────────┘
                       │ 仅在规则无法判断时
┌─ LLM 层（节制调用）─────────────────────────────────────┐
│ · 意图理解（"开始 review PR #42"）                       │
│ · 失败原因分析（规则的补充——解释为什么失败了）              │
│ · 日报生成                                              │
│ · 复杂上下文总结（跨多个 Task）                           │
│                                                       │
│ 每次调用有 token 预算 + 用户可见的价格标签。                │
└──────────────────────┬───────────────────────────────┘
                       │
┌─ 事件层 ──────────────────────────────────────────────┐
│ 监听 Fleet 事件流（已有 Observable Fleet）               │
│ tab 创建/关闭 · 进程 exit · 输出匹配 · 空闲超时           │
└───────────────────────────────────────────────────────┘
```

## 2. 自驱行为清单

### 2.1 规则引擎驱动（零 token）

| 事件 | 规则 | 动作 |
|------|------|------|
| 新 tab 打开，标题含 "PR #N" | 匹配 Pipeline「review PR」 | 通知：「要创建 Task 吗？」[是] |
| 步骤命令执行完毕（exit code） | 匹配成功/失败条件 | 自动推进步骤 / 标记失败 + 展示结果 |
| 活跃 Task 空闲 > 30min | 空闲超时 | 通知：「还在做这个吗？」→ 继续/暂停 |
| tab 关闭，且属于活跃 Task | Task 缺 tab | 通知：「tab 已关闭。Task 缺编辑器。要补充吗？」 |
| 所有步骤完成 | Task 完成 | 通知：「Task 完成。归档？」[归档] |
| 每天 18:00 | 定时 | 展示今日摘要（纯数据，无需 LLM） |
| 切回 Task | 有未完成步骤 | 高亮当前步骤 + 上次结果 |
| 检测到重复 Task（同 PR 已存在） | 去重规则 | 「PR #42 已有活跃 Task。切到它？」 |

### 2.2 LLM 驱动（按需、有节制）

| 场景 | 触发条件 | Token 预算 |
|------|---------|-----------|
| 意图理解 | 用户输入非关键词文本 | ~500 |
| 步骤失败分析 | 规则引擎标记失败 + 用户点「分析原因」 | ~800 |
| 日报生成 | 用户输入「今天做了什么」或定时触发 | ~1000 |
| 跨 Task 上下文 | 用户输入模糊的多 Task 查询 | ~600 |

**每个 LLM 调用标注 token 消耗 + 等待指示器。** 用户知道什么时候在花钱。

## 3. 规则引擎细节

### 3.1 规则定义

```json
{
  "rules": [
    {
      "name": "步骤命令完成",
      "when": {
        "event": "tab_output_match",
        "tab_in": "active_task.tabs",
        "pattern": "exit_code: (\\d+)"
      },
      "then": {
        "if_match": "capture[1] == '0'",
        "action": "advance_step",
        "else_action": "mark_step_failed",
        "notify": "步骤 {step.name}: {result}"
      }
    }
  ]
}
```

### 3.2 规则来源

| 来源 | 说明 |
|------|------|
| **内置** | 通用规则（tab 创建/关闭、exit code 匹配、空闲超时） |
| **Pipeline 自带** | 每个步骤的完成条件就是一条规则 |
| **用户定义** | 高级用户可添加自定义规则 |

## 4. Token 预算模型

```
每个 Task 的 token 预算：
─────────────────────────────
规则引擎处理     0 tokens    （步骤推进、状态更新、事件响应）
LLM 意图理解     500          （创建 Task 时，仅一次）
LLM 步骤分析     800          （仅失败时，按需触发）
LLM 日报         1000         （每天一次，按需触发）
─────────────────────────────
每个 Task  ≈ 500-1300 tokens（而非 v6 的 2400）
一天 5 Task ≈ 2,500-6,500 tokens（v6 的 12,000）
```

## 5. 界面更新

在 Task 步骤条上标注 token 消耗：

```
┌─ review PR #42 · 步骤 2/4 ─────────────────────────┐
│                                                      │
│  ✓ 看 diff                                 14:20    │
│  ● 跑测试                                  14:20~   │
│    cargo test --pr                                   │
│    结果: 3 passed, 1 failed                           │
│    [重新跑]  [分析原因 🧠~300tk]  [跳过]               │
│  ○ 写评论                                            │
│  ○ 提交 review                                       │
│                                                      │
│  今日 token: ████░░░░░░ 1,200 / 10,000               │
└──────────────────────────────────────────────────────┘
```

- `🧠` 标记 = 这个动作会调用 LLM，有 token 消耗
- 底部显示当日 token 用量（用户可控）

## 6. 分阶段

```
Phase 0 — 规则引擎 + 手动 Task（零 LLM）
├─ 规则引擎监听 Fleet 事件
├─ Pipeline 步骤手动推进
├─ 内置规则（tab 事件、空闲检测、exit code 匹配）
└─ 零 token 消耗

Phase A — LLM 节制接入
├─ 意图理解（创建 Task 时）
├─ 步骤失败分析（手动触发 🧠 按钮）
├─ Token 预算显示
└─ 日报生成（每天一次）

Phase B — 自学习
├─ 从用户行为学习 Pipeline
├─ 从规则命中学习规则
└─ 优化 token 使用效率
```
